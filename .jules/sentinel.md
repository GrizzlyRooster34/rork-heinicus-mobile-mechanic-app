## 2025-02-27 - [Sentinel] Fixed Hardcoded JWT_SECRET Fallbacks
**Vulnerability:** Found hardcoded fallback strings for `JWT_SECRET` in `expo/backend/middleware/auth.ts` and `expo/backend/trpc/routes/auth/route.ts` (e.g. `process.env.JWT_SECRET || 'heinicus-mobile-mechanic-app-jwt-secret-key-2025-very-secure-and-long-at-least-64-chars'`).
**Learning:** These fallbacks likely existed to prevent local development environments from crashing when `.env` files were missing or incomplete. However, doing this creates a CRITICAL security risk: if a production deployment accidentally misses the environment variable, the application falls back to a publicly known, hardcoded secret, allowing any attacker to forge valid JWTs and completely bypass authentication or escalate privileges.
**Prevention:** Never use hardcoded fallback strings for cryptographic secrets or API keys. Always enforce strict environment variable checks by throwing a fatal error or failing fast on application startup if they are missing. Use environment validation libraries (like Zod, which is actually used in `expo/backend/env-validation.ts` but the check was being bypassed by these local fallbacks) to ensure configuration integrity.
