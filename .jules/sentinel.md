## 2025-05-24 - JWT_SECRET Hardcoded Fallback & NEXTAUTH_SECRET Misuse
**Vulnerability:** The application was using a hardcoded fallback string for `JWT_SECRET` in both authentication middleware and routes. Additionally, several critical tRPC routes (`admin`, `reviews`, `payments`, `mechanic`) were improperly checking for and verifying tokens against `NEXTAUTH_SECRET` instead of `JWT_SECRET`.
**Learning:** Hardcoded cryptographic secrets allow an attacker to forge JWT tokens if the environment variable is accidentally omitted or if the fallback is discovered in the source code. The inconsistent use of `NEXTAUTH_SECRET` alongside `JWT_SECRET` created a disjointed authentication architecture where routes could fail to authenticate or use the wrong secret entirely.
**Prevention:** Always enforce strict environment variable checks for cryptographic secrets by explicitly throwing an error (failing fast) during initialization if they are missing. Avoid mixing different authentication paradigms (e.g., NextAuth vs. custom JWT) in the same backend unless specifically designed to do so. Ensure that a single source of truth is used for signing and verifying tokens across the application.
