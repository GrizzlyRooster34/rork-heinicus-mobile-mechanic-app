## 2025-04-01 - Hardcoded Auth Secret Fallbacks and Standardizing Secrets
**Vulnerability:** The application was using hardcoded secret fallbacks (e.g. `process.env.JWT_SECRET || 'heinicus-mobile-mechanic-app-jwt-secret-key-2025...'`) for JWT signing and verification, which exposes authentication to severe security risks if the environment variable is omitted or lost in deployment. Some routers also inconsistently referenced `NEXTAUTH_SECRET` instead of `JWT_SECRET`.
**Learning:** Hardcoded fallbacks are likely used as conveniences during development but represent critical vulnerabilities when pushed to production. An inconsistent naming convention for auth secrets across tRPC routes allows configuration errors and potential bypassing of auth validations.
**Prevention:** Always enforce strict environment variable checks (throwing errors when a required secret like `JWT_SECRET` is missing) instead of supplying insecure default strings. Ensure global configuration logic is consistently reused and that single secrets are standardized across all corresponding middlewares and route handlers.
